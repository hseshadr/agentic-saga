AGENTIC SAGA / ARCHITECTUREone host · typed boundaries · evidence before claims

A generic safety kernel for agent-directed work

Smart choices. Hard stops.

Agentic Saga lets an agent choose a next action. A deterministic kernel decides whether that action may affect the world, records enough evidence to recover it, and refuses to call an uncertain outcome “done.”

Honest delivery model

At-least-once attempts plus a stable idempotency identity and reconciliation. Not universal exactly-once side effects.

Definition: two inputs, one kernel boundary

Direct construction starts with a typed SagaDefinition; the definition and policy must use the same ToolRegistry. A canonical definition fingerprint is persisted at creation and checked on resume, so changed policy, tools, invariants, budget, or redaction fail closed. Optional saga.yaml authoring loads a bounded SagaContext; application-owned assembly resolves registered names into the domain definition. A SagaGoal enters separately. The YAML is a public manifest for agent context, not a workflow language or secret store.

Intent: durable before external execution

Outcome: ambiguity is a state, not a guess

Known outcomes are recorded. A timeout, lost response, or crash after dispatch becomes durable unknown work; reconciliation looks up the same logical operation. Bounded read failures become a durable ReadUnavailable observation rather than invented provider state. A retry can reuse an effect identity only when absence is proven or deduplication covers the recovery horizon.

02 / authoring & quotas

Choose the input. Keep the contract.

Applications may construct typed contracts directly or load bounded YAML. Business execution remains registered application code, so ecommerce demonstrates the library without becoming part of the core.

Direct typed construction

Library users build a SagaDefinition, create application-owned collaborators, then call the supported compose_runtime(...) factory. Lower-level constructors remain available for advanced manual assembly.

runtime = compose_runtime(
    store=store,
    definition=definition,
    policy_context_provider=contexts,
    terminal_gate=terminal_gate,
    invariant_evidence_provider=evidence,
    clock=clock,
    worker_id="ecommerce-1",
    id_namespace=b"ecommerce/v1",
)

Optional saga.yaml authoring

A bounded public manifest gives an agent portable objective, quota, tool, proof, and escalation context. It contains public values and versioned secret references—not credentials. The loader rejects unknown references, unsafe YAML, and credential-shaped values before planning. Ecommerce excerpt:

objective: Fulfill the order or restore a verified safe state.
tools:
  allowed: [reserve_inventory, charge_payment]
checks:
  success: [order_fulfilled]
escalation:
  conditions: [unknown outcome after safe reconciliation]

The ecommerce manifest and context-manifest contract show the boundary. Every generic JSON boundary is bounded to 16 levels deep, 4,096 total nodes, 256 items per container, 16,384 characters and 16,384 UTF-8 bytes per string, and 65,536 canonical UTF-8 bytes.

The SagaDefinition-owned RedactionPolicy adds application-classified sensitive keys to a non-configurable built-in floor for credential keys, bearer strings, and card-like values. Unlisted ordinary PII remains public, so the application must classify it.

ExecutionBudget is a four-field deterministic planning quota. For each planning turn, elapsed and output-token reservations use floor(total / turns); the remainder stays unused.

turn_limitMaximum agent planning turns.
tool_call_limitCounts durable read starts, effect intents, and compensation intents.
elapsed_ms_limitTotal planning-call allowance reserved in fixed per-turn slices.
token_limitTotal maintained-adapter output allowance reserved in fixed per-turn slices.

The maintained OpenRouter adapter applies the output-token cap and planning-call deadline. These quotas are not meters for input tokens, actual token usage, end-to-end Saga time, money, or provider spend; provider account controls own spend enforcement.

03 / proof or stop

Trust is a boundary, not a feeling.

The library validates data at its typed boundaries. It deliberately does not pretend to sandbox code already installed in the host process.

UNTRUSTED

Model proposals, manifests, commands, outcomes, and evidence JSON cross strict size and shape bounds. Redaction runs before durable public evidence is written. None of this input grants authority.

COOPERATIVE HOST CODE

Installed drivers and typed adapters are application code. They must honor cancellation, stable identity, and their declared provider capabilities.

ISOLATE OUTSIDE THE CORE

Hostile Python, native extensions, and deliberately adversarial plugins need an external process, container, or service.

Happy path — verified finish

Fresh deterministic invariant evidence must prove the intended business state. A terminal status is not a provider’s assertion and not a model’s claim.

  • Intent is durable before an adapter call.
  • Projection rebuild must reproduce ledger state.
  • Success is SUCCEEDED_VERIFIED.

Business failure — verified compensation

When the goal cannot finish safely, confirmed effects enter a reverse dependency frontier. Every compensation is a new durable effect with its own outcome evidence.

  • History is never erased.
  • Only confirmed obligations are reversed.
  • Repair is COMPENSATED_VERIFIED.

Compensation failure or unknown — reconcile, then stop

A known compensation failure remains durable for recovery planning. A timeout, crash, or lost response becomes unknown work and must reconcile against the same operation identity.

  • Absence proof may permit a safe retry.
  • Ambiguity never becomes success.
  • Unsafe ambiguity becomes quiescent HUMAN_REQUIRED.

Human resolution — authenticated transaction

The store-owned verifier authenticates the exact ephemeral HumanDecision during the SQLite commit. The transaction binds its actor, Saga sequence, action, and canonical public digest to the pending durable request.

  • Policy code cannot authenticate the resolution.
  • Failed authentication changes no ledger state.
  • Automation resumes only after durable resolution.

05 / limits

Precise boundaries make recovery credible.

Agentic Saga provides local durable coordination around external systems. It does not convert them into one transaction or make an unsafe integration safe by naming it an adapter.

SQLite reference backend

  • POSIX-only: the immediate parent must be private and owner-controlled; database, WAL, SHM, temporary, backup, and restored files are regular, current-user files hardened to 0600.
  • Backup and restore publish to a fresh destination only. Existing leaves and symlinks fail closed rather than being overwritten.
  • Use a local filesystem with normal POSIX link and lock semantics. Root, another same-UID process, unusual mount behavior, and external ACL policy remain outside this process boundary.

Local Flight Recorder

  • Materialization requires POSIX descriptor support and a fresh, empty destination; packaged assets are limited to at most 200 static files and 32 MiB total.
  • The read-only server binds 127.0.0.1:<actual port> and requires that literal authority in its exact Host header.
  • Origin and Sec-Fetch-Site are independently optional. When present, Origin must be the exact loopback origin and fetch site must be same-origin or none.
  • It serves GET and HEAD only, with a 240-character request path and an 8 MiB served-file limit.
  • A 1-second header deadline, 40-header and 16 KiB header bounds, 8 concurrent handlers, and an 8-request listen backlog limit local resource use.
  • No universal exactly-once side effects or atomic cross-service commit.
  • No high availability, multi-host writer support, or serializable cross-Saga isolation from the SQLite reference backend.
  • No automatic resolution when safe reconciliation cannot establish an opaque provider outcome; HUMAN_REQUIRED is durable and quiescent.
  • No containment for hostile native or Python plugins inside the core library.
